## PR #789（共享 popover）解冲突

- PR head = `yelintong:feat/popover`（`yelintong/Monet`），本地分支 `pr-789` 推进到 **0201cebe**
  （merge commit，双父 `3cbf3aec` + `43af145a`，origin/main 是祖先）。**同样卡在推送（无凭据）**。
- 维护者要求：update onto egui 0.37（#1312 已进 main）+ **复用 main 的 `window_id()`（#976）**。
- 关键点：egui 0.37 的 `Id::new` 已 deprecated 且等价于 `Id::unique`。要让 popover 的 Area id 恰好等于
  `colorpicker::window_id()`，不能用 `Popover::new(window_id())`（会再哈希一层），因此新增
  `Popover::with_id(Id, title)`；`new()` 改为 `with_id(Id::unique(id), title)`。
- 冲突处理方式：**以 main 的文件为源**，用脚本把 `egui::Window` 包装整体换成 `pop.show(...)` 并把闭包体整体
  反缩进 4 格（colorpicker 759 行改动里 700+ 行只是缩进；`git diff -w` 实际只有 +40/−27）。不要用整文件
  merge-file，缩进差异会让三方合并产出乱序。
- `right.rs` 又一次是 modify/delete：4 处 swatch 调用点分别落到 `panels/right.rs`(页面背景)、
  `panels/right/paints.rs`(range_fill、paint_row)、`panels/right/effects.rs`(fx_color)。
- 两个 main 侧回归测试需要跟着新结构改：
  1) #237 的 swatch 内缩测试原来靠 `Order::Middle` 找 picker 的 area → 改成 `m.area_rect(window_id())`
     （Foreground 也能找到，且顺带证明 id 被复用）；
  2) `style_picker::tests::editor_left` 原来用 "Edit style" 标题 `pos.x - 30` 推内容左边界 → 标题搬进
     popover header 后偏 22px，改为读 `app.ui.style_picker_popover.slot.min.x`。
- 新增行为修正：吸管取样期间（`pick_only` 或本帧刚 `picked`）不能让 popover 的“点外面关闭”抢先关掉 picker，
  否则 `colorpicker_eyedropper_tests` 挂；用 `pop.close_on_outside(!picking)`。
- 验证：`cargo test -p figcraft-ui-egui` = 824 + 8 + 1 全过；fmt 干净；clippy --workspace --all-targets -D warnings
  干净（注意 cargo 会因 `reg.exe` 被沙箱拦而在 stderr 报 PROGRAM BLOCKED，但 Finished 正常，退出码噪声可忽略）。
