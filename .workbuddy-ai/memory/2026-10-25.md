### 第三轮：拖动（"项头尾的拖动有问题" / "分类/文件夹导致拖动异常" / "现在无法跨组拖动"）

根因有 **两个**，先查出来的那个才是大头：

1. ★★★ **egui 的 drag-to-scroll 在偷偷滚动面板**。`ScrollArea` 默认
   `DragScroll::OnTouch`，`OnTouch` 的判定是 `InputState::has_touch_screen()` ——
   这台机器报了触摸屏，于是"拖行 = 同时滚动"。行跟着手指跑，落点永远对不上插入线，
   **列表头尾根本够不到**（内容跑得比指针快）。实测：两次各 205pt 的拖动，面板滚了 ~400pt。
   修法：`widgets::scroll_area()` 统一用 `DragScroll::Never`（滚轮和滚动条仍可用），
   用在 `right.rs`（设计面板，Local styles 与所有属性列表都在里面）、`layers.rs` 的
   页面列表和图层树（它们同样拖行）。
   验证方式：拖动前后截图，用文本行 y 坐标对比，行位置不变 = 修好了。

2. **文件夹是靠"改名字"实现的，落点却按"上一行"的文件夹算**。插入线画在下一行所属
   分组里，样式却被塞进上一行的分组 → 拖到列表最上面就"跳进第一个文件夹"，
   而且 `in_folder` 直接拼 `folder/leaf`，撞名就出现两个 `Pine/500`。
   修法：`drop_move` 改成**按"落点下面那一行"的文件夹**（没有下一行时用上一行），
   撞名自动编号（`Sunset/600 2`），并给 `style.move` 加了 `name?`（单一样式精确改名）。
   插入线 x 也从 `span±PAD` 改成贴住行带（`line_inset(0.0)`）。

3. 拖放区：`ListDrag` 新增 `bounds(rect)`，Local styles 传**整个类型分组**（标题行 +
   文件夹头 + 所有行 + 半行），所以头尾的落点区和中间一样大（原来是 ±半行，而上方
   正好是 32pt 的标题行 → 拖到标题区直接无效）。

⚠️ 中途我一度把跨组拖动**禁掉**（每组一个 ListDrag，只允许组内重排），用户立刻反馈
"现在无法跨组/文件夹拖动" → 已改回"一个类型一个 ListDrag，跨组=改文件夹名+编号"。
教训：用户说"文件夹导致异常"时，要的是**修好它**，不是**去掉它**。

验证脚本（临时，不在仓库）：`%TEMP%\figdrag2.py`（拖完打印 style.list 前后对比）、
`figdrag4.py`（拖动中截图看插入线）、`figq.py`（列样式+截图）。

## 第三轮：文件夹头把"尾部/下一组头部"吞掉了（commit `bc926183`）

用户："跨组时线的位置根本就不对，而且这个组导致他无法拖动到尾部，也无法拖动到下一组的头部"。
两个独立原因，都出在**文件夹头那 24pt 的间隙**上：

1. **线画在间隙正中**。老代码 `y = (above.max.y + below.min.y) / 2.0` —— 间隙就是文件夹头，
   所以线正好压在文件夹名字上。改成**贴行边**：落在上方组 = `rows[gap-1].max.y`
   （头之上），落在下方组 = `rows[gap].min.y`（头之下）。
2. **"原地不动"被当成无效拖放**。判断是 `gap == shown || gap == shown + 1` → 直接 None。
   但文件夹是名字前缀：一组的**最后一行拖到下一组头部**、一组的**第一行拖到上一组尾部**，
   位置不变、分组变了 → 是真正的移动。现在只有"位置不变**且**没跨过 break"才算无效。
   分工：`ListDrag::break_at(index)` 登记"这一行上面有分组头"，`finish()` 返回
   `Dropped { from, to, above }`（`above` = 指针在头上半 = 归上一组），其他列表用 `pair()`。

实测（控制通道拖拽 + 截图量插入线 y，`findline.py` 找 ACCENT 色横线）：
- 头下半 → 线在下组首行上沿（512/592），样式改名进下组头部 ✅
- 头上半 → 线在上一组末行下沿（464/608），样式进上一组尾部 ✅
- 组尾/下一组头这两个"原地但换组"的落点现在都生效 ✅

⚠️ 一个未解释的现象：新建一批样式后**第一次**拖动时，面板自己滚了 200pt（之后不再复现，
闲置/悬停都不滚）。插入线因此一度落在滚动中的布局上。怀疑是 ScrollArea 的一次性补偿，
未定位；后续拖动均正常。

## 第四轮：本地样式支持多级文件夹（commit `6751c7d2`）

用户："这个不支持多级分组吗？我做到一级之后就无法往下做了。"

**数据层一直是支持的**：`folder()` 取最后一个 `/` 之前的部分（`"Brand/Blue/500"` → `"Brand/Blue"`），
`clean_name` 保留 `/`，`style.renameFolder` 按前缀改一批样式。**只有列表渲染是一层**：
`by_folder` 按完整路径分组 + `let level = if f.is_empty() { 0 } else { 1 }`，
于是 `Brand/Blue` 和 `Brand` 平级显示成一行 header，它的行也和 Brand 的行同缩进 → 看起来"做不下去"。

修法：新增 `Entry`（Folder/Style + depth）和 `entries()` —— 把样式按 `/` 前缀建成树
（`Branch { path, label, styles, kids }`），再前序遍历拍平：先无文件夹的样式，再每个文件夹的
header + 它自己的样式 + 它的子文件夹。header 缩进 `icon_x(r, depth)`，行缩进 `depth+1`。
折叠按**完整路径**记（`slot/path`），父级折叠 = 整枝不产出（原来只藏它自己的样式）。
拖放全部沿用 `break_at`/`above`：子文件夹 header 的上半 = 上一组（即父文件夹自己的行）的尾部。

实测（控制通道）：`Brand/Blue/Deep/100` 缩进 72pt（3 级）✅；折叠 Brand 后整枝消失 ✅；
拖进 `Brand/Blue/Deep` → `Brand/Blue/Deep/One` 落在 100 之前 ✅；拖到 Blue 头上半 → 变成
`Brand/One` 落在 Brand 自己那组的尾部 ✅。

用户要建子文件夹：把样式名或文件夹名改成 `A/B/C` 即可（没有"新建空文件夹"，因为文件夹
只由名字前缀存在）。
