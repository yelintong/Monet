## Variables 面板组拖动：浅层级落点跨子树 bug（已修）

**现象**：从第 3 层往第 1 层拖，落点插到第 1 层组「后面、它的子项前面」，
子项看起来像被挂到了新拖入的组下面（其实是 flat 顺序里父组和子组之间被插了一刀）。

**根因**：`group_drop_slot` 的落点是「指针边界下方那一行」的位置；`apply_group_drop`
的 `at` 也直接取该行在 `ordered` 里的下标。层级比锚点行浅时，锚点是某个祖先的**后代**，
插在它前面 = 插到祖先和祖先的孩子之间。组是由变量名路径派生的，父子关系跟顺序无关，
所以视觉上子项被"孤儿化"。

**修法**（`crates/ui-egui/src/variables_panel.rs`）：
1. `group_drop_slot`：先算出「落点要当谁的兄弟」`sib` = 锚点 id 截到 `level` 段；
   `after = level < anchor_level || bottom`；落点槽位 `slot` = `sib` 子树里最后一个可见行的下一行
   （`rposition` 找 `id==sib || id.starts_with("sib/")`），否则 `sib_row`。
   线条 `y` 画在 `slot` 那行的顶边 —— 线条 = 真实落点。
2. 抽出纯函数 `group_insert_index(ordered, sib, after)`：`after` 时取 `sib` 子树最大下标 +1，
   否则取 `sib` 下标。`apply_group_drop` 用它算 `at`。
3. 测试：把旧的 `group_drop_line_stays_at_the_pointer_boundary`（断言线条停在指针边界）
   换成 `group_drop_shallow_level_lands_after_the_subtree`（断言线条/落点跳到子树末尾）。

**验证**：`variables_panel` 6 passed、`variables_view` 42 passed、`cargo build -p figcraft` EXIT=0；
App 已重启，控制端口 55425。

**注意**：启动方式 —— `Register-ScheduledTask` 现在被拒（拒绝访问）；
可用 `Bash + dangerouslyDisableSandbox + run_in_background` 直接跑 `target/debug/figcraft.exe`，
进程能活过本轮。杀进程用 `taskkill //F //IM figcraft.exe`（需禁沙箱）。

## 真正的 bug：守卫把「拖到浅层级」整个吞掉（已修）

**现象**：第 2 层的组拖到第 1 层，线显示第 1 层，松手后**还在第 2 层**（缩进都没变）。
「拖别人也一样」——不只是拖自己。

**根因**：`apply_group_drop` 开头那句守卫
```rust
if let Some(t) = d.target && (ids[t] == old || ids[t].starts_with(&old_pref)) { return; }
```
指针落在**被拖组自己的行或其子树里**时锚点就是它自己/它的后代，守卫直接 return →
改名和重排全跳过，所以原地不动。而「往浅层级拖」恰恰经常满足这个条件。

**修法**：抽出 `drop_is_noop_or_cycle(old, anchor, level)`：
`inside = anchor == old || anchor.starts_with(old/)`，只有 `inside && level >= old_level`
才算原地/成环；**比自身浅的层级是合法的「移出去」，必须放行**。

**验证**：新增端到端测试 `apply_group_drop_moves_a_level_two_group_out_to_level_one`
（真实 `FigApp::new(Session::new(), NoServices)` + `variable.create` 造 `ar/sh/button` 等），
断言拖 `ar/sh` 到第 1 层后变量变成 `sh/button`、`ar/sh/*` 消失、顺序 = `["ar","ar/xx","sh","space"]`。
`variables_panel` 8 passed，build EXIT=0，App 重启在 55425。

**教训**：用户说「还在原位/层级没变」= 改名都没发生 = 一定有 early return，
先找守卫，别去调线条和落点算法。

## 变量面板组行：仿图层的整块选中 + 新尺寸（已做）

`group_rows` 重写成两趟：先 `allocate_exact_size` 把所有可见行收进 `Vec<Drawn{g,r,resp,level}>`，
再按 marks（2=选中组、1=后代）算连续 run，**一个 run 画一个圆角整块**（`selected_row_child`），
选中那行再叠一条 `selected_row` 的带（只有块的首尾角圆），最后才画每行内容。
之前是每行各自 `rect_filled` + 上下各 4pt 内缩 → 行与行之间有 8pt 缝，看起来是一堆小块。

新尺寸（`const INDENT: f32 = 24.0`，最终版，用户第二次修正后）：
- **高亮块（悬停/选中那条）左边 = 8**（从行外框算；`r` 已 shrink 8，所以 `base = r.min.x`）。
- 块内：**4 → 16 图标 → 8 → 文字**（文字左 = `x0 + 28`）；图标**占位 24**（slot 从块左起，
  `ui.interact` 用 24×24），但**画出来的图形是 16**（`icons::paint` 给 16×16 rect）。
- 全部变量（无箭头）：文字左 = `x0 + 4`。
- 每级缩进 24；`group_drop_slot` 的层级判定 `floor((p.x-base)/24)+1`、插入线 `x0 = base+(level-1)*24`。
- 选中行的深色带也用同一 `x0`（按 level 缩进），和悬停块对齐。

**验证**：`variables_panel` 8 passed、`variables_view` 42 passed；截图量像素（ppp≈1.78）：
高亮块左=行外框+8、图形=块左+4、文字=块左+28、L1→L2 文字差 42px≈24 逻辑。App 在 55425。

**坑**：截图是物理像素（2520×1575，ppp≈1.78），`ui.input` 用逻辑坐标（= 物理/1.78），
点之前要先换算。另：模拟点击可能把 egui 的按下状态带进持久化内存，重启后出现「拖拽幽灵 + 插入线卡住」，
发一次 move+down+up 到空白处即可清掉。
